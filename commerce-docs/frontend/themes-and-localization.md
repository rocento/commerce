# Themes, languages and markets

Theme contracts originate in [backend/theme-contract.json](../../commerce-api/rocento-api/theme-contract.json). The shared API-client copy is generated by `node commerce-ops/scripts/sync-theme-contract.mjs`; React renders known registered components and allowlisted tokens. Configuration cannot name imports or execute arbitrary code. Product list, product detail and cart slots retain existing shopping behavior. Optional section failures are isolated; invalid public configuration uses the bundled default, while invalid draft preview shows an error.

Published snapshots are immutable. Targeting selects a published theme from ordered channel rules using supported customer segment, delivery zone, stock and manually selected city conditions. City selection affects presentation; actual delivery eligibility still uses location. Theme resolution refreshes on relevant login/location/city changes and periodically revalidates published state.

Draft preview uses the existing authenticated administrator session and the owning channel's preview permission. `theme_preview` is an identifier, not a secret. Configure admin `VITE_STOREFRONT_URL` and storefront `VITE_SALES_CHANNEL`; deployment must support intentional same-site authenticated preview. Theme configuration is not a substitute for session sharing or ingress policy.

## Translation boundaries

Catalog translations are prepared as drafts and reviewed against current source text. They share product IDs, prices, stock, SKU and slugs. Editing a draft translation does not publish another content locale. [Admin localization](../admin-ui/content-and-settings.md) describes permission and review flows.

The separate shopping interface uses English/Arabic message forms with plural-aware formatting and plain-text rendering. Shopper interface preference is origin-scoped and persists through available browser storage; locale changes should not remount cart or checkout. Interface language is distinct from published content routes, price currency and theme direction. Inspect current [interface implementation](../../commerce-web/apps/storefront/src/interface-locale.tsx) when adding strings.

## Market overlays

One market can be published per installation; others remain editable drafts. Published overrides determine effective assortment and prices without rewriting source catalog values. Source-inactive products cannot be enabled by an overlay. Draft edits do not change live prices. Orders retain market/release context and quote admission revalidates current facts.

Concurrent shopper country switching, independent market payment/delivery/tax policies and a multi-country domain resolver are outside this implementation. Publication currently uses the configured default content locale. [Backend market semantics](../backend/catalog-and-markets.md) is the authority for readiness, price application and restore behavior.
